# FORMA

**Сфоткай еду. Похудей на результат.**

Бесплатное фитнес-приложение с ИИ-подсчётом калорий по фотографии
и социальной лентой историй «до → после».

Ни подписки. Ни регистрации. Ни сборки.

## Почему это отличается от YAZIO и MyFitnessPal

Мы разобрали 7 фитнес-приложений. Почти у всех **фото-сканер еды — платная функция**:
YAZIO PRO, MyFitnessPal Premium, Lose It! Premium, Noom Plus — от 600 до 900 ₽ в месяц
только за то, чтобы сфотографировать тарелку.

В FORMA фото-сканер **бесплатный**. Это не маркетинг, а следствие архитектуры:
приложение не хранит данные на чужом сервере и не платит за вычисления — ему нечего
продавать, кроме рекламы, а её тут нет.

| | FORMA | YAZIO | MyFitnessPal | Lose It! | Noom |
|---|:--:|:--:|:--:|:--:|:--:|
| Фото-сканер | **бесплатно** | PRO | Premium | Premium | Plus |
| Цена | **0 ₽** | ≈600 ₽ | ≈750 ₽ | ≈700 ₽ | ≈900 ₽ |
| Лента историй «до/после» | **есть** | — | — | — | — |
| Работа без аккаунта | **есть** | — | — | — | — |
| Данные хранятся локально | **есть** | облако | облако | облако | облако |

## Быстрый старт

### Вариант А — без всего

Двойной щелчок по **`index.html`**. Всё. Ни Node.js, ни сети, ни аккаунта не нужно.

### Вариант Б — статикой (нужно для пушей и установки как приложение)

```bash
python -m http.server 8899
```

- приложение → http://localhost:8899/index.html
- сайт → http://localhost:8899/site/index.html

> Пуши и «установить как приложение» требуют `http://` или `https://` —
> на `file://` браузер их запрещает.

### Установка как приложение (PWA)

Chrome/Edge на Android или десктопе: значок установки в адресной строке,
или **Настройки → Установить приложение**. После установки работает офлайн.

## ИИ-сканер (бесплатно)

Три бесплатных провайдера на выбор. Ключ вводится в
**Настройки → ИИ** и хранится **только в вашем браузере** — он не уходит
на наш сервер, потому что нашего сервера просто нет.

| Провайдер | Ключ | Модель | Примечание |
|---|---|---|---|
| **Gemini** | [aistudio.google.com/apikey](https://aistudio.google.com/apikey) | `gemini-2.0-flash` | бесплатный tier, принимает фото |
| **Groq** | [console.groq.com/keys](https://console.groq.com/keys) | Llama 3.2 Vision | очень быстро |
| **Офлайн-эвристика** | не нужен | — | без сети и ключей: цвет фото + ключевые слова |

Плюс можно указать **любой OpenAI-совместимый endpoint** — OpenRouter
(бесплатные `:free` модели с vision), Ollama локально или свой Cloudflare Worker.

**Лимита нет** — ни пятого скана, ни «Premium». Именно это и отличает FORMA
от конкурентов, у которых фото-сканер стоит денег.

**Без ключа приложение тоже работает** — подставляются типовые значения,
чтобы можно было пользоваться дневником, пока не задан ключ.

> **Честно про точность:** визуальный ИИ ошибается на **20–30 %**. Поэтому
> результат всегда можно поправить руками — это нормально и не стыдно,
> так работает любой сканер. Не принимайте решение о здоровье по одной оценке.

## Тесты

17 автонаборов: 13 браузерных и 4 для настоящего Android. Браузерные
поднимают статический сервер сами и гасят его после себя — запускать можно
по одному и в любом порядке.

```bash
cd .verify
npm install          # единственная зависимость: ws

node routes.mjs          # 18/18  маршруты + проверка DOM-маркера каждого
node interact.mjs        # 14/14  лайки, комментарии, сторис, скан, экспорт
node content.mjs         # 15/15  на экранах живой контент
node theme.mjs           # 23/23  стили классической темы + гарантия «бесплатно»
node mobile.mjs          # 15/15  ширина телефона, нет горизонтального скролла
node site.mjs            #  7/7   лендинг
node gps.mjs             #  трекинг, ручный режим, GPX/CSV
node counts.mjs          #  счётчики данных
node api.mjs             # 20/20  мост к Worker

node assets.mjs           # 72/72  index.html ≡ sw.js ≡ манифест
node bundle.mjs           # 26/26  собранный phone/www — то, что реально едет в APK
node android-manifest.mjs # 12/12  разрешения Android не теряются при сборке
node file-protocol.mjs    #  6/6  приложение работает по file:// (двойной щелчок)
```

Три последних ловят то, что не видит браузер:

- **`bundle.mjs`** проверяет не исходники, а **собранный бандл**: каждый
  ресурс отдаётся без 4xx, все 15 маршрутов рендерятся, `classic.css`
  применился, service worker заглушен. Ошибка в `prepare.mjs` иначе
  проявилась бы только на телефоне — белым экраном.
  Перед запуском нужен `cd phone && npm run bundle`.
- **`assets.mjs`** сверяет три списка ассетов, которые живут отдельно
  (`index.html`, `sw.js`, `manifest.webmanifest`). Расхождение не роняет
  страницу сразу — оно тихо ломает офлайн и установку PWA. Уже находило
  забытый в списке кэша `api.js`.
- **`android-manifest.mjs`** требует 5 разрешений и необязательные
  `uses-feature`. Шаблон Capacitor объявляет только `INTERNET`, поэтому
  камера, GPS и уведомления без ручного дописывания не работают.

`theme.mjs` специально следит за обещанием «бесплатно и без лимита»: если
кто-то снова добавит счётчик сканов или кнопку Premium, тест упадёт.
Раньше такой paywall в коде был — и противоречил лендингу.

`routes.mjs` проверяет не « view непустой», а **конкретный маркер в DOM** для
каждого маршрута (`#rc-eat`, `#c-post`, `#up-follow` …). Это обязательно:
роутер для неизвестного пути молча показывает главную, и она непустая —
поэтому наивный тест зелёный, даже когда маршрут вообще не работает.

### Проверка на настоящем Android

Четыре набора заходят в WebView **установленного APK** через DevTools-протокол
и проверяют то, чего не видит ни один браузерный тест: что ассеты реально
маршрутизируются в нативной обёртке.

```bash
npm --prefix phone run apk:release   # единственный верный способ сборки
adb install -r phone/android/app/build/outputs/apk/release/app-release.apk
adb shell am start -n app.forma.fit/.MainActivity

cd .verify
node device-eval.mjs     # заголовок, фон, Fit.store, навигация, непустой #app
node device-routes.mjs   # 13/13 маршрутов + ловля JS-ошибок в рантайме
node device-deep.mjs     #  6/6  вложенные маршруты с параметрами + маршруты 404
node device-recipe.mjs   #  7/7  все 10 рецептов открываются и пишут в дневник
```

Вся обвязка вынесена в **`device.mjs`**: `launch()` поднимает приложение,
дожидается сокета `webview_devtools_remote_<pid>`, пробрасывает порт и
переподключается, если процесс Android убьётся. Сами тесты занимают по
30–40 строк и не содержат CDP-рутины.

Три вещи, на которые здесь уже наступали:

- **Собирать APK только через `npm run apk:release`.** Скрипт сначала
  запускает `cap sync android` — Gradle сам копирует `phone/www` в ассеты.
  Голый `gradlew assembleRelease` собирает «успешный» APK со **старым**
  JS: сборка зелёная, APK ставится, правок в приложении нет.
- **Ждать конкретный элемент, а не `sleep(900)`.** Холодный старт на
  эмуляторе занимает до 10 с, и часть «падений» была чисто гонкой.
- **Пользоваться публичным API, а не ключами хранилища.**
  `Fit.store.get("nutrition")` — не то же самое, что
  `Fit.store.getNutrition(Fit.today())`, который реально пишет дневник.

## Бэкенд (необязательно)

`worker/` — Cloudflare Worker + D1 для общей ленты. Приложение работает и без него;
мост включается, только когда задан адрес.

```bash
cd worker
npm install
npx wrangler d1 create forma-db      # вписать database_id в wrangler.toml
npx wrangler d1 execute forma-db --file=./schema.sql
npx wrangler deploy
```

Потом указать адрес Worker в `assets/js/api.js` (`WORKER_URL`).

## Сборка для телефона (Android APK)

Только телефоны. **Сборки под ПК нет по требованию.**

Всё живёт в `phone/` — это отдельная обёртка Capacitor, которая не трогает
корень репозитория. Приложение по-прежнему остаётся «просто файлами»: сборщика
и минификатора нет, в APK едет ровно то, что лежит в корне.

```bash
cd phone
npm install
npm run bundle   # собрать phone/www из исходников (без этого APK будет белым)
npm run apk      # bundle + cap sync + gradle assembleDebug
```

Готовый файл:

```
phone/android/app/build/outputs/apk/debug/app-debug.apk   (~3.8 МБ)
```

Поставить на телефон:

```bash
adb install -r phone/android/app/build/outputs/apk/debug/app-debug.apk
```

Или скопировать `.apk` на телефон и открыть — нужно разрешить установку
из неизвестных источников.

### Что делает `prepare.mjs`

Просто копирует в `phone/www` те файлы, на которые ссылается `index.html`,
и делает две вещи, которых нельзя делать «в лоб»:

1. **Выкидывает `sw.js`.** Внутри APK офлайн обеспечивает нативный слой,
   а service worker на схеме `capacitor://` не проходит — только сыплет
   ошибками в консоль. Регистрация в `core.js` при этом гасится, иначе был бы 404.
2. **Проверяет, что все ссылки из `index.html` реально есть** в бандле.
   Ошибка копирования иначе проявилась бы только на телефоне — белым экраном.

### Разрешения

Шаблон Capacitor добавляет только `INTERNET`. Приложению нужно больше,
поэтому `phone/android/app/src/main/AndroidManifest.xml` дописан руками:

| Разрешение | Зачем |
|---|---|
| `ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION` | карта и трекер пробежки (`/activity`) |
| `CAMERA` | ИИ-сканер еды — съёмка фото с камеры |
| `POST_NOTIFICATIONS` | локальные пуши (на Android 13+ это runtime-разрешение) |

Камера и GPS помечены `required="false"`, чтобы приложение ставилось и на
устройства без них.

### Если сборка падает

- `Your project path contains non-ASCII characters` — AGP не любит кириллицу в пути.
  Уже снято флагом `android.overridePathCheck=true` в `phone/android/gradle.properties`.
- `Could not find com.android.tools.build:gradle` — нужен доступ в интернет:
  Gradle сам скачивает свои зависимости при первом запуске.
- Требуется JDK 17 и Android SDK (`ANDROID_HOME`). Проверено на Temurin 17.0.19
  и SDK 34.

### Про подпись

`npm run apk` даёт **debug-сборку** — она подписана отладочным ключом, который
Gradle создаёт на автомате. Устанавливается и работает, но для Google Play
нужен свой ключ:

```bash
cd phone/android
keytool -genkey -v -keystore forma-release.keystore \
        -alias forma -keyalg RSA -keysize 2048 -validity 10000

cp keystore.properties.example keystore.properties   # заполнить пароли
cd .. && npm run apk:release
```

Результат — `app-release.apk` (~3 МБ, меньше debug за счёт оптимизации ресурсов).
Ключ и `keystore.properties` в git не попадают: потерянный ключ делает
невозможным обновление приложения в Play, поэтому храните его отдельно.

## Ограничения

- **Лента и сторисы локальные**, пока не задеплоен Worker. Демо-люди и демо-посты
  создаются при первом запуске, чтобы приложение не выглядело пустым. Схема кода
  уже рассчитана на настоящий бэкенд.
- **Ключ ИИ лежит в браузере.** Для публичного релиза понадобится свой прокси,
  иначе ключ можно вытащить из устройства самого пользователя.
- **Это не медицинское изделие.** При беременности, хронических заболеваниях
  и целях вне −5/+5 кг нужен врач, а не приложение.
