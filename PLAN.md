# FORMA — план проекта

> **Сфоткай еду. Похудей на результат.**

Бесплатное фитнес-приложение с ИИ-распознаванием еды по фото, персональным планом
похудения и социальной лентой историй «до → после».

**Статус:** MVP готов и проверен. Редизайн в классическую тёмную тему сделан, бэкенд
для ленты написан (Cloudflare Worker + D1, 41/41 тестов), APK для Android собирается
одной командой. Все 13 автотестов зелёные.

---

## 1. Проблема и решение

**Проблема.** Человеку, который хочет похудеть, нужен ответ на вопрос «сколько калорий и БЖУ
в этой тарелке?». Существующие приложения требуют:
- искать продукт в списке из 500 000 позиций и вводить граммы вручную (10–15 минут в день);
- **заплатить** за ИИ-распознавание по фото (YAZIO PRO, Lose It! Premium, Noom Plus).

Мы проанализировали рынок и сделали ставку на то, что **фотография еды — это ожидаемое
поведение**, и оно должно быть бесплатным.

**Решение.** FORMA — приложение, где камера вместо поиска, а сообщество вместо
мотивационных баннеров. Бесплатно, без регистрации, с данными в своём браузере.

## 3. Название и бренд

**FORMA** — от *forma* (форма, латынь): работа над телом как произведение формы.
Читается одинаково на любом языке, короткое, влезает в иконку, не конфликтует
с существующими фитнес-брендами.

- Слоган: **«Сфоткай еду. Похудей на результат.»**
- Позиционирование: бесплатная альтернатива YAZIO и MyFitnessPal.
- Палитра (после редизайна): графит `#0b0d11`, карточка `#14181f`, акцент —
  приглушённое золото `#d9b26a` с градиентом `#e8cf9a → #c9a25c`.
  Золото вместо неонового зелёного: неоновые приложения выглядят как «инфоцыганские»,
  золото на графите читается как «серьёзный продукт». Есть светлая тема.

## 4. Функции (MVP — реализовано)

### 4.1 Питание
- **ИИ-сканер по фото** — камера или загрузка изображения, распознавание блюда и БЖУ.
  Поддержка Gemini 2.0 Flash, Groq Llama Vision, OpenAI-совместимый endpoint.
- **Офлайн-режим** — если ключа нет, приложение не ломается: подставляет типовые значения.
- **Дневник питания** — кольца по БЖУ, счётчик воды, цель по калориям.
- **База продуктов** (30 позиций), свои продукты, рецепты (10 блюд с фильтрами).
- **Прогресс по БЖУ** — дневник с историей.

### 4.2 ИИ-коуч
- **Чат** по похудению с учётом контекста (история сообщений, последние 8 реплик).
- **Генератор плана на неделю** — считает BMR/TDEE, целевые калории, раскладывает
  БЖУ и меню по дням, добавляет тренировку и совет на каждый день.
- Ключ хранится **только в браузере** пользователя.

### 4.3 Тренировки
- **67 упражнений** с группами мышц и гайдами.
- **4 готовые тренировки** — для дома без инвентаря и для зала.
- Счётчик подходов, таймер, отметки о выполнении.

### 4.4 Социальное (наш козырь)
- **Истории «до → после»** — публикация своего результата с фото и цифрами.
- **Лента** — посты с лайками, комментариями и «красивыми» реакциями.
- **Профили пользователей** — публичная история прогресса.
- **Рейтинг прогресса** — сколько кг потерял каждый участник.
- 6 демо-людей с правдоподобными данными, чтобы лента не выглядела пустой.
- 8 типов реакций, 6 наборов «красивых» фраз поддержки.

### 4.5 Мотивация
- **Челленджи** (4 шт.) — вода, шаги, без сахара и т.п., с серией дней.
- **Значки/ачивки** (10 шт.) — за находки в приложении.
- **Пуш-уведомления** — 7 сценариев: вода, взвешивание, недобор белка, тренировка и др.
  Работают и через Web Push, и через локальный планировщик в приложении.

### 4.6 Прочее
- **Активность** — карта (шаги/тренировки) и дневная норма.
- **Прогресс** — график веса, замеры тела, фото до/после.
- **Профиль** — вес, рост, возраст, цель, расчёт BMR/TDEE.
- **Настройки** — провайдер и ключ ИИ, темная/светлая тема, экспорт данных, очистка.
- **PWA** — устанавливается как приложение, работает офлайн, иконки и манифест.

**Итого: 13 экранов, 17 маршрутов, 76 методов хранилища, 49 экспортируемых модулей.**

## 5. Архитектура

### Принцип: ноль зависимостей
Приложение — это статические файлы, которые открываются двойным кликом по `index.html`.
Нет сборки, нет `node_modules`, нет фреймворка. Это гарантия, что оно не сломается
через год и его можно проверить целиком.

```
index.html
├── sw.js                      Service Worker (офлайн-кэш)
├── manifest.webmanifest       PWA-манифест
├── icons/                     Сгенерированные PNG-иконки
├── assets/css/
│   ├── styles.css             Базовая тема, токены, тёмная + светлая
│   ├── components.css         Карточки, кольца, кнопки, формы
│   ├── mobile.css             Мобильные правки
│   └── classic.css            РЕДИЗАЙН — классическая тема, грузится последним
├── assets/js/
│   ├── data.js                31 КБ — упражнения, продукты, рецепты, значки
│   ├── store.js               14 КБ — состояние + localStorage + миграции
│   ├── ai.js                  27 КБ — распознавание фото, чат, генератор плана
│   ├── push.js                 7 КБ — уведомления и планировщик
│   ├── social.js               9 КБ — люди, истории, лента, рейтинг
│   ├── api.js                  8 КБ — мост к Worker (необязателен)
│   ├── core.js                16 КБ — роутер, layout, иконки, графики, загрузка
│   ├── views.js               49 КБ — 6 базовых экранов
│   ├── views_gps.js            карта, трекинг, экспорт GPX/CSV
│   └── views_social.js        51 КБ — 7 новых экранов
├── worker/                    Cloudflare Worker + D1: лента, сторис, профили
└── site/                      Маркетинговый сайт
```

**Про `classic.css`.** Это отдельный слой, который только переопределяет, а не
переписывает базу. Так сделано намеренно: имена классов — несущая конструкция
для селекторов `core.js` и всех 10 тестовых наборов, и переписывание `styles.css`
на месте сломал бы всё разом. Графики на canvas читают цвета из CSS-переменных
(`chartInk()`), поэтому тоже следуют за палитрой и светлой темой.

**Порядок загрузки скриптов критичен:** `data → store → ai → push → social → core → views → views_social`.
`views_social.js` идёт последним, потому что переопределяет маршрут `/settings`.

### Архитектурные решения

| Решение | Почему |
|---|---|
| Хеш-роутинг | Работает с `file://` и с сервера, не требует настройки |
| `localStorage` + миграции | Нет сервера → нет расходов; `migrate()` чинит старые версии данных |
| Шаблонные строки вместо DOM-билдеров | Читаемо, ноль рантайм-зависимостей |
| `Fit.*` как единственная точка входа | Порядок загрузки виден и контролируем |
| ИИ-слой с офлайн-фолбэком | Приложение не должно «умирать» без ключа |
| `classic.css` поверх, а не вместо | Имена классов несущие — переписывание базы ломает всё разом |
| Свои файлы в SW — сеть, кэш как запасной | Cache-first отдавал старые файлы и правки не доезжали до пользователей |

### Ограничения (осознанные решения)
- Соцсеть локальная: данные ленты — `localStorage` + демо-сид. Код специально
  структурирован так, чтобы позже подключить Cloudflare Worker (папка `worker/`).
- Точность фото-оценки ±20–30 %. Это ограничение любого визуального ИИ, и мы
  показываем пользователю долю от нормы, а не «истину».

### Этап 11 — Сборка для телефона (Android APK) ✅
Обёртка в Capacitor, **только Android — для ПК не делаем по требованию.**
`index.html` при этом продолжает открываться двойным щелчком: сборщика и
минификатора нет, в APK едет ровно то, что лежит в корне.

`phone/` — отдельный проект, не трогающий корень репозитория:

| Файл | Роль |
|---|---|
| `prepare.mjs` | копирует в `phone/www` файлы из `index.html`, выкидывает `sw.js`, проверяет что все ссылки есть |
| `capacitor.config.json` | `app.forma.fit`, `webDir: www`, схема `https` |
| `android/` | Gradle-проект Capacitor (генерируется, в git не входит) |

Результат: `phone/android/app/build/outputs/apk/debug/app-debug.apk`, 3.8 МБ.

Три решения, которые пришлось принять:

1. **`webDir` не может быть `.`.** Иначе в APK уедут `site/`, `worker/`, `phone/`
   и два чужих файла по 75 МБ. Отдельный `www/` решает это, но означает
   ручное копирование — а ошибка копирования видна только на телефоне
   (белый экран). Поэтому `prepare.mjs` сверяет список файлов с `index.html`.
2. **`sw.js` в APK не нужен.** Офлайн обеспечивает нативный слой, а service
   worker на схеме `capacitor://` не регистрируется. Регистрация в `core.js`
   гасится, иначе на каждом запуске был бы 404.
3. **Права дописаны вручную.** Шаблон Capacitor даёт только `INTERNET`,
   а приложению нужны геолокация (карта пробежек), камера (сканер еды) и
   уведомления. Без них три функции работали бы только в браузере.

Найденная при сборке особенность окружения: рекурсивный `cpSync` на этом томе
(OneDrive поверх NTFS) роняет Node с `0xC0000409`. Обход — копировать файлы
поштучно.

`bundle.mjs` (26/26) проверяет **собранный бандл**, а не исходники: ни одного
4xx на ресурсы, все 15 маршрутов рендерятся, `classic.css` применился,
service worker заглушен, обещание «бесплатно без лимита» живо.

Проверено на настоящем Android 14 (эмулятор, API 34): APK ставится, запускается
без падений, WebView отдаёт заголовок `FORMA — Сфоткай еду. Похудей на результат.`,
фон классической темы применён, все 5 маршрутов переключаются прямо в нативной
обёртке. Для этого есть `device-eval.mjs` и `device-routes.mjs` — они заходят в
WebView установленного APK через DevTools-протокол и ловят ошибки рантайма.

`assets.mjs` сразу нашёл расхождение: `assets/js/api.js` подключался в
`index.html`, но отсутствовал в списке кэша `sw.js` — офлайн был бы дырявый.

## 7. Как запустить

Приложение работает **без сборки и без сервера**:

```
Вариант А: открыть index.html двойным кликом
Вариант Б: поднять статику
  python -m http.server 8899
  → http://localhost:8899/index.html
  → http://localhost:8899/site/index.html  (сайт)
```

Чтобы включить ИИ-распознавание: **Настройки → Провайдер** и вставить бесплатный ключ
Gemini (`aistudio.google.com`) или Groq (`console.groq.com`). Без ключа работает офлайн-режим.

### Как проверить

```bash
cd .verify
npm install
node routes.mjs     # 17 маршрутов, ошибки консоли
node interact.mjs   # 14 сценариев взаимодействия
node content.mjs    # 15 экранов с реальным содержимым
node theme.mjs      # 17 проверок редизайна
node mobile.mjs     # 15 маршрутов на ширине телефона
node site.mjs       # 7 проверок маркетингового сайта
node gps.mjs        # трекинг, ручной режим, экспорт
node counts.mjs     # счётчики данных
node api.mjs        # мост к Worker, 20 проверок
cd ../worker && node test/local.mjs   # 41 проверка Worker и D1
```

Каждый скрипт сам поднимает свой сервер — запускать можно в любом порядке и по одному.
